# IMPLEMENTATION_PLAN: תוכנית המימוש של TimeFlow v2

ההבטחה: **A calmer way to focus, one step at a time.**
העיקרון: המערכת עשירה מאחורי הקלעים, אבל בכל רגע רואים רק את מה שצריך עכשיו.

המסמך מתאר מה נבנה, באיזה סדר, ולמה נבחרה כל טכנולוגיה. מה שבוצע בפועל, עם תוצאות הבדיקות, מתועד ב-`CHANGELOG.md`.

---

## 1. החלטות טכנולוגיות

| החלטה | הבחירה | למה |
|---|---|---|
| שרת | Flask, כמו בשלד של Pretech | הפרויקט כבר בנוי עליו. אין סיבה להחליף |
| ממשק | HTML ו-CSS בלבד, **בלי JavaScript** | דרישת הקורס: כל הלוגיקה ב-Python. זה גם מאפשר מדיניות CSP שחוסמת כל סקריפט, הגנה חזקה מפני XSS |
| מסד נתונים | SQLite דרך `sqlite3` המובנה | בלי התקנה. שאילתות עם פרמטרים בלבד, ולכן אין SQL injection. קל להחליף ל-PostgreSQL כי כל ה-SQL מרוכז בקובץ אחד |
| שכבת נתונים | `repository.py`, בלי ORM | כל שאילתה מסננת לפי `user_id`. קל להסביר ולבדוק. SQLAlchemy היה מוסיף תלות ושכבת למידה |
| סיסמאות | `werkzeug.security` (scrypt) | מותקן עם Flask. ספרייה מוכרת ומתוחזקת |
| אסימונים | `itsdangerous` (חתימה עם תוקף) | מותקן עם Flask. משמש לאימות מייל, איפוס סיסמה, הסרה מדיוור וקישור למשוב |
| CSRF | אסימון ב-session, נבדק בכל POST | מימוש קצר וברור, בלי Flask-WTF |
| AI | `anthropic` (Claude), דרך השרת בלבד | המפתח נשאר בשרת. בלי מפתח יש מצב הצעות בסיסי שמוצג בגלוי |
| מייל | `smtplib` המובנה, עם מצב "קובץ" לפיתוח | בפיתוח המיילים נשמרים בתיקייה במקום להישלח, כדי לבדוק בלי חשבון |
| Google Calendar | OAuth 2.0 עם `urllib` המובנה | הרשאת קריאה בלבד. בלי ספריות Google הכבדות |
| בדיקות | `unittest` המובנה | רץ בכל מחשב עם `python -m unittest`, בלי התקנה |
| הגדרות וסודות | קובץ `.env` (לא עולה לגיט) או משתני סביבה | קורא קטן ב-`config.py`, בלי python-dotenv |

**ספרייה חדשה אחת בלבד: `anthropic`.** הצורך: חיבור מאובטח ל-Claude. תאימות: Python 3.9 ומעלה. היא נטענת רק כשמשתמשים בה, ולכן האתר עולה גם בלעדיה.

## 2. מבנה הקוד החדש

```
adhd-time-manager/
├── app.py                      השלד של Pretech + init_app(app)
├── timeflow/
│   ├── __init__.py             מחבר את כל החלקים לאפליקציה
│   ├── config.py               קריאת .env והגדרות
│   ├── db.py                   חיבור, יצירת טבלאות, גרסאות סכמה, גיבוי
│   ├── schema.sql              כל הטבלאות
│   ├── repository.py           שכבת הנתונים: כל ה-SQL, תמיד לפי user_id
│   ├── security.py             CSRF, כותרות אבטחה, התחברות כברירת מחדל, הגבלת ניסיונות, אסימונים
│   ├── accounts.py             הרשמה, התחברות, אימות מייל, איפוס, מחיקת חשבון
│   ├── texts.py                כל הטקסטים בעברית ובאנגלית
│   ├── ui.py                   אייקונים, ניווט ועזרים לתבניות
│   ├── planner.py              הצעד הבא וסדר המשימות
│   ├── journey.py              מסע הכדור הפורח
│   ├── focus_timer.py          מכונת המצבים של הטיימר
│   ├── personalization_engine.py   מנוע ההתאמה האישית (Python טהור, בלי מסד)
│   ├── learning_data.py        מכין את הנתונים למנוע מתוך המסד
│   ├── snooze_assistant.py     ניהול השיחה ב-Snooze
│   ├── ai_providers.py         ספקי AI: Claude ומצב בסיסי
│   ├── mailer.py               שליחת מיילים, הסיכום היומי והתזמון
│   ├── google_calendar.py      OAuth ו-Calendar API
│   └── views/                  הנתיבים, קובץ לכל אזור
├── templates/zehava/           התבניות
├── static/                     CSS, תמונות, צלילים
├── tests/                      בדיקות אוטומטיות
├── v1-original/                הקוד של גרסה 1 כמו שהיה (רק ב-zip)
├── tools/make_sounds.py        יוצר את קובצי הצליל (יצירה מקורית, בלי זכויות של אחרים)
└── docs/                       ארכיטקטורה, פרטיות, תוצאות בדיקות
```

שכבות: **נתיב (views) → לוגיקה (planner, journey, focus_timer, engine) → נתונים (repository) → SQLite.** הנתיבים לא כותבים SQL, והלוגיקה לא מכירה את Flask.

## 3. מודל הנתונים

לכל טבלה: מזהה מספרי יציב, `user_id` (בעלות), `created_at` ו-`updated_at`, ומחיקה מדורגת (`ON DELETE CASCADE`) כשמוחקים משתמשת.

| טבלה | תוכן | כללים |
|---|---|---|
| `users` | מייל, שם, hash של הסיסמה, מתי אומת המייל | מייל ייחודי |
| `user_settings` | שפה, ערכת צבעים, תנועה, צליל, אורכי מיקוד והפסקה, התראות, מצב רגוע, הסכמות, דיוור | ערכים מוגבלים ב-CHECK |
| `tasks` | כותרת, הערה, קטגוריה, עדיפות, תאריך ושעה, מצב, מתי התחילה והושלמה, כמה נדחתה | |
| `task_steps` | צעדים בתוך משימה | נמחקים עם המשימה |
| `notes` | פתקים, צבע, תגית | |
| `focus_sessions` | סשן מיקוד או הפסקה: מתוכנן, בפועל, השהיות, מצב | **רק סשן פעיל אחד למשתמשת** (אינדקס ייחודי חלקי) |
| `journey_events` | נקודות במסע: משימה, צעד, סשן | **ייחודי לכל פריט**, אין ספירה כפולה |
| `journey_state` | איפה הכדור הוצג בפעם הקודמת | לאנימציה בלבד |
| `daily_pulse` | דירוג יומי וסיבה | אחד לכל יום |
| `insights` | תובנות שהוצגו ומה המשתמשת בחרה | להשהיית הצעות שנדחו |
| `sound_feedback` | "עזר לי" לכל מרחב צליל | |
| `snooze_entries` | מחשבות שנפרקו, מיון ותשובת העוזר | |
| `ai_requests` | מתי היו בקשות AI ומה התוצאה, **בלי התוכן** | להגבלת שימוש ועלות |
| `email_log` | מה נשלח, מתי ומה הסטטוס | **ייחודי למשתמשת ויום** עבור הסיכום היומי |
| `login_attempts` | ניסיונות התחברות | להגבלת ניסיונות |
| `google_accounts`, `calendar_events` | אסימוני Google, ואירועים שמורים (עם `task_id` כשאירוע הפך למשימה) | ייחודי לכל אירוע, אין כפילויות |

**מעבר מ-v1:** ב-v1 אין נתונים שמורים (הכול היה בזיכרון), ולכן אין מה להעביר. הקובץ `mail_config.json` הישן עדיין נקרא אם הוא קיים. לגרסאות הבאות יש טבלת `schema_version` ופונקציית מיגרציה ששומרת גיבוי של המסד לפני כל שינוי.

## 5. מה תלוי בשירות חיצוני

| יכולת | מה צריך | בלי זה |
|---|---|---|
| עוזר AI ב-Snooze | `ANTHROPIC_API_KEY` | הצעות בסיסיות מכללים, עם הודעה גלויה שה-AI לא מחובר |
| מייל אמיתי | חשבון SMTP (למשל Gmail עם סיסמת אפליקציה) | המיילים נשמרים בתיקייה `instance/outbox` |
| Google Calendar | פרויקט ב-Google Cloud עם OAuth Client ID ו-Secret | היומן הפנימי (משימות עם תאריך) עובד, והחיבור מסומן "לא הוגדר" |
| שליחה כשהאתר סגור | שרת שרץ, או Task Scheduler / cron שמריץ את פקודת השליחה | השליחה מתבצעת כשהשרת פועל |
